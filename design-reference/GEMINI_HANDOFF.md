# Gemini 实施说明

从仓库根目录打开本项目。需要完成医百顺患者端的可交互网页，本地预览即可。先用设计资料复原页面，再用虚构数据跑通业务流程。用户已确认按[页面关系](PAGE_RELATIONSHIPS.md)起步，并允许后续根据原稿调整推断关系。

## 如何读取素材

1. [页面关系](PAGE_RELATIONSHIPS.md)定义一级导航、模块入口、按钮、去向、返回和关键状态。用这里出现的 Figma 节点 ID 定位画板。
2. [画板目录](FRAME_CATALOG.json)把每个 Figma 节点 ID 映射到本地 PNG、所属 Figma 页面、画布层级和尺寸。大画框的 PNG 用作总览，内部画板可单独读取。按当前模块逐张读图。
3. [界面文字索引](SCREEN_TEXT)按 Figma 页面分组，记录每张画板的代表性可见文案、位置和首段字体信息，便于先用文本定位、再用 PNG 核对。源文件的完整画布关系见 [Figma 盘点](FIGMA_INVENTORY.json)。
4. [素材索引](SOURCE_ASSETS.json)用于查找原始图片和 SVG，路径相对于仓库根目录。优先复用这些源文件，并保留 Figma 裁切和比例。索引中带有 `archive` 的 SVG 可从仓库内的 ZIP 提取；带有 `releaseArchiveUrl` 的原图使用同一私有仓库的补充附件，按 `member` 路径解压到项目目录。常用参考 PNG 可直接从仓库读取。「发现-小视频」另有 [逐图层规范](FIGMA_SPEC.md)、[图层数据](figma-layers.json)和[设计值](design-tokens.json)作为精确还原样例。
5. 每次实现先列出使用的画板 ID、入口和状态，再对照图像复核。把标为备份、组件、注释或画框总览的内容当作参考。状态稿复用同一个页面结构，正式业务画板才是导航目的地。

画板目录内 `redacted-png` 标记含证件、联系方式、报告、条码或票据区域的脱敏参考。保留页框和流程位置，模拟数据使用虚构内容。缺失的独立素材在素材索引标明，相关画板仍可用截图和结构识别。

### 依据有冲突时

- 用「页面关系」决定演示流程，用对应 Figma 画板决定视觉和源文案。原稿无原型连线，点击目的地属于经确认的产品推断。
- 同名或后缀为备份的画板先比较主要内容、尺寸和父级。存在多个有效状态时，保持文档指向的主稿，并把其余状态放在相同业务实体下。
- 实现真实的按钮、表单、列表、弹层和导航。画板 PNG 用来比对。按每张画板的宽高、字体、层级、间距和裁切设计；375 px 是多数画板参考宽度，部分源稿为 360 px。

## 按业务跑通

| 流程 | 本地可验证的路径 | 状态与回写 |
| --- | --- | --- |
| 导航与搜索 | 首页切发现、咨询记录、我的；搜索医生、医院、科室或资讯 | 返回恢复原标签、筛选和搜索词；无结果可清除或改写搜索词。 |
| 登录和就诊人 | 触发登录 → 模拟验证码或一键登录 → 恢复动作；新增或选择就诊人 → 回填表单 | 取消回原页；已有输入保留；退出登录回到游客状态。 |
| 挂号 | 医院 → 科室 → 有号医生/时间 → 选就诊人 → 确认 → 模拟支付 | 生成一条可从订单找回的记录。无号时回列表选择其他号源。 |
| 问诊和会话 | 医生 → 图文/电话/视频 → 填病情和预约信息 → 模拟支付 → 咨询记录 → 会话 → 完成/评价 | 免费团队咨询进入相应会话。订单和咨询记录引用同一个咨询；模拟通话具备待接通、接通、结束。 |
| 发现 | 分类 → 视频、直播、预告、回放或文章 → 点赞、关注、预约、收藏、评论 | 预约与关注同步列表。行动从详情返回原来源；外部分享使用本地反馈。 |
| 报告和医疗工具 | 报告查询 → 详情；核酸预约或查询 → 订单/报告；病例夹、用药助手、就诊人增改 | 覆盖空结果、预约渠道失效、提醒开关和默认就诊人。已保存模拟记录可在列表找回。 |
| 处方、药品与商城 | 会话/订单 → 处方 → 结算配送；我的 → 商城 → 商品/套餐 → 加购或购买 | 过期处方和不可在线支付按状态处理。购物车、地址、配送、收货和订单关联一致。 |
| 订单与发票 | 我的 → 订单状态 → 详情；待付款支付或取消；符合条件的订单售后和开票 | 带订单类型和 ID。状态变化同步列表、详情和消息。取消或失败后可回到原页或按原状态重试。 |

## 本地数据与运行

- 编排虚构的医生、就诊人、病例、订单、会话、报告、评论、药品、直播和用户记录。初始样例及本地媒体放在项目目录内。对象用稳定 ID 关联，订单或会话从不同入口访问时仍是同一记录。
- 用本地状态模拟切换、提交、取消、付款结果和记录更新。按实现方式决定本地持久化；页面刷新后继续演示的记录应可恢复。提供重置样例数据的方式。
- 用项目内图片或本地演示素材表现视频和直播状态。登录、验证码、支付、发票、报告和就诊行为使用模拟反馈。网页启动、浏览和完成演示路径无需远程 API 密钥或真实身份数据。
- 目标是浏览器中可完整演示。无需发布、部署、绑定域名或接入真实后台。用户可以后续调整页面关系和样例数据。

## 验收条件

1. 四个一级入口可达，关键路径能够往返，返回点与来源一致。
2. 以画板目录逐模块核对主要页面及弹窗、空状态、错误态、订单状态；用截图比较对应画板，不把画板导出图当网页实现。
3. 用户、就诊人、订单和会话从不同入口读取同一模拟状态，临时取消不创建订单，重复确认不会新建重复记录。
4. 清洁安装后能在本地启动并构建。启动、运行及演示路径无需部署或访问外部服务。
5. 在交付说明里列出已实现的模块、仍以模拟表现的状态，以及调整过的推断关系。
